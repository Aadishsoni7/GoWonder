# Offbeat: research, content and implementation handoff

Prepared on 18 October 2026 for the existing Offbeat app.

This pack supplies the actual task drafts and structured data, not just a request for more research. It preserves the 233 existing IDs, the saved research and the 60 licensed portraits. The accompanying app revision applies the three levels, People directory, optional curiosity check, saved stage progress and navigation changes.

## What is included

| Deliverable | Coverage |
| --- | ---: |
| Discovery entries with three authored levels | 233 |
| Distinct level tasks | 699 |
| Existing people retained | 60 |
| Newly sourced profiles | 38 |
| Total people entries | 98 |
| Existing licensed local portraits | 60 |
| Map entries with documented field connections | 130 |
| Map entries using labelled broader stories | 103 |
| Resource records, including new practitioner sources | 82 |
| Unique URLs in the source inventory | 203 |

The 699 tasks include specific starter exercises, practice projects, later tools and a reflection question for each field. They are editorial starter drafts, not professional instruction or a claim that an untrained person can independently perform specialised work. Observation, simulation and supervised learning alternatives are included where appropriate.

## Give Codex these files

1. `01-Implementation-brief.md` explains the required behaviour and includes a copy and paste implementation prompt.
2. `content-pack.json` contains all pathways, people, resource assignments, evidence states and next connections.
3. `02-All-fields-and-levels.md` is the readable field by field handbook, grouped by world.
4. `03-People-and-sources.md` lists all 98 people with current story copy and sources.
5. `source-register.json` distinguishes saved sources, newly checked sources and videos whose playback still needs checking.
6. `specialist-research-queue.json` contains a specific brief for each of the 103 entries without an exact specialist. Some are category roots and should use a gallery, not an artificial specialist claim.
7. `validation.json` records structural coverage and explicitly states the remaining verification limits.

Codex should read the brief and data together. It can improve layout, interaction, accessibility and wording, while preserving the specific tasks and evidence distinctions. It should not replace the supplied content with generic repeated paragraphs.

## What is still an editorial task

The pack does not claim an exact person for every niche. Broader field stories are labelled, so they can offer a human connection without falsely claiming that person performs the exact work. The new 38 profiles also need reusable portrait permission or licence evidence. Source only cards are a deliberate interim presentation, not a substitute face.

Dedicated source coverage is uneven. Some records have a useful broader source rather than a dedicated tutorial. The source register contains 203 unique URLs, but not every external link, redirect or video embed has been retested. A named person's undocumented first discovery, routine or habits must stay undocumented rather than being manufactured to fill a template.

The accompanying revision passes TypeScript, production compilation and complete internal content checks. Fresh browser checks cover people search, opening a person story, distinct wildlife levels, saved completion after reload, the notebook, bird photography on a 390px phone viewport, and the optional curiosity check with skipped questions and explained results. This is representative functional verification, not a claim that all 699 experiences or all external resources were manually exercised.

## Next implementation quality rule

A discovery entry is ready when its description makes sense, its task is specific, its three stages differ, its person connection is honestly labelled, its source opens, and its reflection leads somewhere useful. Increasing the catalogue count is not a substitute for those checks.
